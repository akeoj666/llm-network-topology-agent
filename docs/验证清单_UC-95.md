# UC-95 在 Packet Tracer 里的验证清单

文件：`out\UC-95.pkt`（单臂路由 VLAN 互通，模型全自动生成）

拓扑：R1 `Fa2/0` ←直通线→ SW0 `Fa0/24`（trunk）；SW0 下挂 6 台 PC。

| 设备 | 接口 | 归属 | IP |
|---|---|---|---|
| PC0 / PC1 / PC2 | Fa0 | VLAN 10 RD | 192.168.10.10 / .11 / .12 |
| PC3 / PC4 / PC5 | Fa0 | VLAN 20 FIN | 192.168.20.10 / .11 / .12 |
| SW0 | Fa0/1–0/3 | access VLAN 10 | — |
| SW0 | Fa0/4–0/6 | access VLAN 20 | — |
| SW0 | Fa0/24 | trunk | — |
| R1 | Fa2/0 | 承载，无 IP | — |
| R1 | Fa2/0.10 | dot1Q 10 | 192.168.10.1/24 |
| R1 | Fa2/0.20 | dot1Q 20 | 192.168.20.1/24 |

---

## 开跑前两件事

1. **确认在 Realtime 模式**（右下角时钟，不是 Simulation 秒表）。
   仿真模式下 ping 要手动点播放，容易误判。
2. **打开后等 30 秒**再测。STP 要收敛，ARP 要学。
   **第一次 ping 丢 1–2 个包是正常的**，不要当成故障。

---

## 第 1 关：线是不是通的（目视）

打开后看连线颜色：

- 六条 `PC → SW0` 的线应该是**绿色三角**
- `SW0 Fa0/24 → R1 Fa2/0` 也应该是**绿色**

如果某条线是**橙色/黄色**，说明 STP 还在收敛，再等一会儿；
如果一直是**红色**，那个口没 up，点开设备看是不是没 `no shutdown`。

> 串口线才会是红色（本用例没有串口线，如果看到红线说明接错了）。

---

## 第 2 关：交换机的 VLAN 表

点 **SW0** → `CLI` 标签 → 回车 → 敲 `enable` 进特权模式（提示符从 `>` 变 `#`），然后：

```
show vlan brief
```

期望（端口列表顺序可能不同）：

```
VLAN Name                             Status    Ports
---- -------------------------------- --------- -------------------------------
1    default                          active    Fa0/7, Fa0/8, Fa0/9, Fa0/10
                                                Fa0/11, Fa0/12 ... Fa0/23
10   RD                               active    Fa0/1, Fa0/2, Fa0/3
20   FIN                              active    Fa0/4, Fa0/5, Fa0/6
1002 fddi-default                     active
1003 token-ring-default               active
1004 fddinet-default                  active
1005 trnet-default                    active
```

**要对上的三件事：**

- `10 RD` 存在，端口是 `Fa0/1, Fa0/2, Fa0/3`
- `20 FIN` 存在，端口是 `Fa0/4, Fa0/5, Fa0/6`
- **`Fa0/24` 不在任何 VLAN 的端口列表里**——这是对的，trunk 口不属于任何单个 VLAN

如果 VLAN 10/20 压根不出现，这一关就废了（之前 UC-05 踩过这个坑：
VLAN 数据库不在 running-config 里，而在设备 XML 的 `<VLANS>` 节点）。

---

## 第 3 关：trunk 有没有起来

SW0 上继续：

```
show interfaces trunk
```

期望：

```
Port        Mode         Encapsulation  Status        Native vlan
Fa0/24      on           802.1q         trunking      1
```

**关键看两个词：`802.1q` 和 `trunking`。**
如果 Status 是 `not-trunking` 或 `down`，跨 VLAN 一定不通，这关没过。

---

## 第 4 关：路由器的子接口

点 **R1** → `CLI` → `enable`：

```
show ip interface brief
```

期望：

```
Interface              IP-Address      OK? Method Status                Protocol
FastEthernet2/0        unassigned      YES unset  up                    up
FastEthernet2/0.10     192.168.10.1    YES manual up                    up
FastEthernet2/0.20     192.168.20.1    YES manual up                    up
FastEthernet3/0         unassigned      YES unset  administratively down down
Serial0/0              unassigned      YES unset  administratively down down
Serial1/0              unassigned      YES unset  administratively down down
```

**四个要点：**

1. `Fa2/0`（父接口）：**没有 IP，但必须是 `up / up`**。
   父口是 down 说明线或对端口有问题，子接口再好也没用。
2. `Fa2/0.10`：`192.168.10.1`，`up / up`
3. `Fa2/0.20`：`192.168.20.1`，`up / up`
4. `Serial0/0`、`Serial1/0`、`Fa3/0` 是 `administratively down`——**这是对的**，
   本用例用不到，主动关掉了。不是故障。

顺便看路由表：

```
show ip route
```

应有两条直连路由：

```
C    192.168.10.0/24 is directly connected, FastEthernet2/0.10
C    192.168.20.0/24 is directly connected, FastEthernet2/0.20
```

---

## 第 5 关：ping（这一步才是结论）

点 **PC0** → `Desktop` → `Command Prompt`。

### 5.1 同 VLAN（应该通，TTL 128）

```
ping 192.168.10.11
```

期望：

```
Reply from 192.168.10.11: bytes=32 time<1ms TTL=128
```

**TTL 是 128**——同 VLAN 走二层，不过路由器，TTL 不减。

### 5.2 跨 VLAN（应该通，TTL 127）

```
ping 192.168.20.10
```

期望：

```
Reply from 192.168.20.10: bytes=32 time=1ms TTL=127
```

**TTL 是 127**——过了 R1 一跳，TTL 减 1。
**这一个数字就是单臂路由生效的证据。** 如果 TTL 还是 128，说明包根本没经过路由器，
那所谓"互通"是假的。

### 5.3 打网关（验证子接口）

```
ping 192.168.10.1
```

应通。不通说明 PC 的网关或 R1 子接口有问题。

---

## 通过标准

四条全中才算这个用例真的成立：

- [ ] `show vlan brief` 有 10 RD（Fa0/1-3）和 20 FIN（Fa0/4-6）
- [ ] `show interfaces trunk` 的 Fa0/24 是 `802.1q` + `trunking`
- [ ] R1 的 `Fa2/0.10` 和 `Fa2/0.20` 都是 `up/up` 且有地址
- [ ] PC0 → PC3 **能通且 TTL=127**

---

## 不通的时候按这个顺序查

| 症状 | 最可能原因 | 在哪看 |
|---|---|---|
| 同 VLAN 也不通 | STP 没收敛 / 口没起来 | SW0 `show interfaces status`，看 Fa0/1-6 是不是 `connected` |
| 同 VLAN 通、跨 VLAN 不通 | trunk 没起来 | SW0 `show interfaces trunk` |
| 同上 | 或子接口没起来 | R1 `show ip interface brief`，看 .10/.20 是不是 up |
| ping 网关不通 | 子接口 down，或 PC 网关填错 | PC0 `Desktop` → `IP Configuration` |
| 全通但 TTL 都是 128 | 两台 PC 其实在同一个 VLAN | 回头查 `show vlan brief` 的端口归属 |
| 前 1–2 包丢，之后通 | 正常（ARP + STP） | 不用管 |
| `show vlan brief` 没有 VLAN 10/20 | VLAN 数据库没写进去 | 这是生成器的问题，告诉我，我去修 |

---

## 一句话

**只要 PC0 → PC3 能通、且 TTL 显示 127，单臂路由就是真的成立了。**
其余四关是快速定位问题用的，出问题时能直接指到是哪一层断的。
