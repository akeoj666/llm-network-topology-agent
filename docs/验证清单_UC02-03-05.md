## UC-02 OSPF 单区域迁移

拓扑：R1 / R2 / R3 三角串联口互联，各带一个 192.168.10/20/30.0/24 网段。
OSPF 进程 100，全部在 area 0。

在 R1 上：

```
enable
show ip ospf neighbor
```
应看到两条邻居，状态 `FULL/  -`。

```
show ip route
```
应看到 `O` 开头的三条 192.168.x.0/24 路由（本网段是直连 C）。

```
show ip protocols
```
应显示 `Routing Protocol is "ospf 100"`。

**冗余验证**：在 R3 上 `configure terminal` → `interface Serial1/0` → `shutdown`，
回到 R1 上 `ping 192.168.30.10` 应该仍然通（走 R1–R2–R3），
`traceroute 192.168.30.10` 会看到多一跳。测完记得 `no shutdown` 恢复。

PC 验证：PC0 `ping 192.168.30.10` 应通（第一包可能丢，等 OSPF 收敛 30 秒左右）。

## UC-03 分区 OSPF 与末梢区域

拓扑：HQ-R（总部，172.16.1.0/24）— ABR — BR-R（分部，172.16.2.0/24）。
HQ-R 与 ABR 之间的链路在 **area 0**，ABR 与 BR-R 之间的链路和分部网段在 **area 100**，
area 100 配成了 **stub（末梢区域）**。

在 ABR 上：

```
enable
show ip ospf neighbor
```
两条邻居，都是 FULL。

```
show ip route
```
应同时出现 `O`（区域内，area 0 的 172.16.1.0/24）和
`O IA`（区域间，172.16.2.0/24）。

在 BR-R 上 `show ip route`：
- `O IA  172.16.1.0/24` —— 总部网段，区域间路由
- `O*IA  0.0.0.0/0` —— **末梢区域自动下发的默认路由**，这是 stub 生效的标志

在 HQ-R 上 `show ip route`：只能看到 `O` 和 `O IA`，**看不到** 10.0.20.0/30 的明细
（被 ABR 用默认路由挡掉了），这也是 stub 的效果。

PC 验证：PC0 `ping 172.16.2.10` 应通。

> **这一条要重点看**：如果 BR-R 的 `show ip route` 里没有 `O*IA 0.0.0.0/0`，
> 说明 PT 的 OSPF 不接受 `area 100 stub`，或者两端配置不一致。
> 排查顺序：`show run | include area` 看三台路由器上的 area 语句是否都进去了。
> 如果确实不支持，把 `examples\uc03.yaml` 里 ABR 和 BR-R 的 `stub_areas: [100]` 删掉重新生成，
> 其余逻辑不受影响（此时 BR-R 会学到明细路由而不是默认路由）。

## UC-05 VLAN 划分与单臂路由

拓扑：R1 用一根线（Fa2/0）连 SW0 的 Fa0/24（trunk），
SW0 上 Fa0/1–0/3 属于 VLAN10（研发，192.168.10.0/24），Fa0/4–0/6 属于 VLAN20（财务，192.168.20.0/24）。
R1 上配了 `Fa2/0.10`（192.168.10.1）和 `Fa2/0.20`（192.168.20.1）两个 dot1Q 子接口做 VLAN 间路由。

在 SW0 上：

```
enable
show vlan brief
```
VLAN10 下应有 Fa0/1、Fa0/2、Fa0/3；VLAN20 下应有 Fa0/4、Fa0/5、Fa0/6。

```
show interfaces trunk
```
应看到 Fa0/24 处于 `trunking` 状态，`Vlans allowed on trunk` 包含 10、20。

在 R1 上：

```
enable
show ip interface brief
```
`FastEthernet2/0.10` 和 `.20` 应为 `up / up`，各自带地址。

```
show vlans
```
能看到两个子接口的封装关系。

**验证**：
1. 同 VLAN 互通：PC0 `ping 192.168.10.12` 应通（不经过路由器）。
2. 跨 VLAN 互通：PC0 `ping 192.168.20.11` 应通（经 R1 单臂路由转发）。
3. 隔离验证：把 SW0 的 Fa0/2 `shutdown`，PC0 ping PC1 应不通，说明 VLAN 内隔离正常。

> 如果 `FastEthernet2/0.10` 一直是 down，先确认**父接口** `FastEthernet2/0` 是 `up / up`——
> 子接口的状态取决于物理口。本方案里父接口已经显式 `no shutdown` 且不打地址。

## 排查通用套路

PT 回放配置时**遇到第一行非法命令就会中止后面全部命令**，
所以「某台设备只进去了一半配置」通常意味着中间有一行不被支持。

- `show run` 看实际生效到哪一行，最后一行就是出错点附近
- `show ip interface brief` 看哪些接口还是 `administratively down`（说明没跑到 `no shutdown`）
- 路由器 `Router-PT-Empty` 插串口模块后，**没有** Fa0/0，只有 Fa2/0、Fa3/0；Serial 是 S0/0、S1/0

## 实测记录

### UC-05 ✅ 通过（2026-10-21 01:18）

- `show vlan brief`：**VLAN 10 RD**（Fa0/1、Fa0/2、Fa0/3）、**VLAN 20 FIN**（Fa0/4、Fa0/5、Fa0/6），
  VLAN1 只剩 Fa0/7–Fa0/23 和 Gi0/1、Gi0/2
- `show interfaces trunk`：Fa0/24 `802.1q` / `trunking` / native 1，
  `Vlans allowed and active in management domain` = **1,10,20**
- R1 `show ip interface brief`：`Fa2/0.10 = 192.168.10.1 up/up`、`Fa2/0.20 = 192.168.20.1 up/up`
- PC0 → 192.168.10.12（同 VLAN）：**4 发 4 收，0% 丢包，TTL 128**（纯二层转发）
- PC0 → 192.168.20.11（跨 VLAN）：**4 发 3 收，25% 丢包，TTL 127**
  → 首包是 ARP 解析网关，属正常现象；TTL 127 说明确实经过了一跳路由器

**踩过的坑**：第一版只把 `vlan 10` / `name RD` 写进了 RUNNINGCONFIG，PT 静默忽略，
结果端口被划走了、VLAN 却不存在，同 VLAN 都不通。VLAN 库其实在设备 XML 的 `<VLANS>` 节点
（外加 flash 里的 `vlan.dat` 副本），已修。
