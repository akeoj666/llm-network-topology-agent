# 实验 8-1：三层架构小型园区网（UC-83）

> 依据：《8.1 实验8-1 构建采用三层网络架构的小型园区网.pptx》第 5 页的设计图。
> 产物：`out/UC-83.pkt`、`out/UC-83_编址规划.md`、`out/UC-83_configs.md`、`out/UC-83_验收报告.md`。
> 规模：**21 台设备**（5 路由器 + 5 交换机 + 8 主机 + 3 服务器）、424 行配置、5 个 VLAN。

## 一、原始设计 vs 本实现

课件只给了**一张设计图 + 11 个步骤标题**，没给逐步命令。所以下面这张表是
「按图复刻」的结果，**每一条差异都写清楚了原因**，没有藏。

| # | 课件原设计 | 本实现 | 为什么 |
|---|---|---|---|
| 1 | 园区路由器 1941、ISP 路由器 1941 | `Router-PT-Empty` | 骨架里**没有 1941 实体设备**（pkt 里的 `PT-ROUTER-NM-1S` 只是型号库条目）。接口名随之变成 `FastEthernet2/0` 等 |
| 2 | 核心层 3560 多层交换机 MLS2 | 路由器 `Core` | 3560 同样不在骨架里；`ip routing` + SVI 需要真三层交换机 |
| 3 | 汇聚层 3560 多层交换机 MLS0/MLS1 | 路由器 `Agg1` / `Agg2`，用**单臂子接口**（`Fa2/0.10` 等）当 VLAN 网关 | 同上。单臂路由与 SVI 在 IP 层等价 |
| 4 | SVI 网关（`interface vlan 10` + `ip address`） | 单臂子接口（`encapsulation dot1Q 10` + `ip address`） | 路由器没有 SVI；功能等价 |
| 5 | 核心—汇聚用 `192.168.1.0/30`、`192.168.2.0/30` **以太网** | Agg1 那条改**串口**，Agg2 那条仍是以太 | 路由器只有 2 个以太口 + 2 个串口，核心要接 3 个上游，只能有一条走串口。**地址与原设计完全一致** |
| 6 | 4 台接入交换机各直连汇聚层 | SW0→SW1、SW2→SW3、SW3→SW4 **级联** | 汇聚是路由器，只有一个 trunk 口；第二台接入交换机只能级联。级联口的 `switchport trunk allowed vlan` 已按实际流量收窄 |
| 7 | 信息中心 VLAN50 的网关在核心层 MLS2 的 SVI | 落在汇聚层 `Agg2` 的 `Fa2/0.50` | 3560 不可用；核心的口已占满 |
| 8 | 「NAT + ACL 在园区路由器 Router0」 | **ACL 挪到 `Agg2` 的两个业务子接口入方向**；**NAT 未做** | 连带后果：VLAN50 网关下移到汇聚层后，部门流量**不再经过 Router0**，ACL 挂那儿根本拦不住。策略本身是示例（课件只写了「NAT+ACL 在这里」，没给规则） |
| 9 | PC 通过 DHCP 获取地址 | PC 配静态地址 | 本项目没有 DHCP 服务器建模（`ip dhcp pool`）。在 PT 里手工点 PC 的 DHCP 即可切回，地址段已按 DHCP 预留好 |
| 10 | 公网侧 `www.hnust.edu.cn` 218.75.230.30/24 | 同地址，服务器用 `PC-PT` | 骨架里没有 `Server-PT` 实体，功能等价 |
| 11 | 核心层做「路由选择」 | 静态路由链：汇聚→核心→园区→ISP，逐级默认路由 | 课件没指定协议；静态路由是最容易逐跳核对的一种 |

**没做的部分只有两项**：NAT 过载（`ip nat inside/outside` + `overload`）与 DHCP。
两者都属于「设备侧服务」，不是路由配置。

## 三、验收结论（推算，14 条断言全过）

| 断言 | 结果 |
|---|---|
| 同部门两台 PC 互通 | ✅ PC0→PC1 |
| 跨部门互通 | ✅ PC0→PC2、PC0→PC4、PC0→PC6 |
| 部门 → 公网服务器 | ✅ PC0/PC2/PC4/PC6 → SRV2 |
| 部门 → 信息中心 | ✅ PC0→SRV0、PC2→SRV0 |
| 信息中心 → 公网 | ✅ SRV0→SRV2 |
| **部门 C/D → 信息中心被拦** | ✅ PC4→SRV0、PC5→SRV1、PC6→SRV0（`Agg2 FastEthernet2/0.30 in 方向 ACL 100 规则「deny」命中`） |

一致性检查 32 项全过：11 台主机的网关都有效、4 条三层链路的网段两端一致、
每条 trunk 都能把 VLAN 送到网关、ACL 有 permit 兜底。

## 四、这份用例逼出来的三个框架改进

做这个实验时，框架本身暴露了三个问题，都已修：

1. **骨架装不下 21 台设备** → 新增 `tools/make_seed.py`：
   复制设备块造新骨架（换新的 `save-ref-id`、改名、重新加密封装）。
   **副作用**：`.pkt` 现在支持超过 12 台设备的拓扑，不再受骨架规模限制。
2. **交换机 SVI 判据太松** → 原来只要 VLAN 声明了网关，**每台交换机都开一遍 SVI**；
   改成「网关地址是本设备某个接口的地址」才开。
3. **trunk 的 VLAN 检查假设每条 trunk 放行全部 VLAN** → 园区网里每条 trunk 只跑
   一部分 VLAN，误报一片。改成：DSL 声明 `trunk_vlans`，检查器按「这条线实际要跑哪些 VLAN」
   逐条追到网关为止（支持级联）。同时配置里会输出 `switchport trunk allowed vlan ...`。

另外给 DSL 加了两个字段：`seed`（本用例用哪个骨架）、`layer`（规划图里的层次）。

## 五、怎么验

```cmd
python gen.py examples\uc81.yaml -o out --confirm CONFIRM   :: 出 pkt + 规划书
python tools\accept.py examples\uc81.yaml                   :: 只跑验收
```

**在 PT 里要做的**：
1. 打开 `out/UC-83.pkt`，**先等 30–60 秒**（STP 收敛 + ARP 学习）
2. `PC0 ping 192.168.50.1`（部门A → 信息中心）→ 通
3. `PC4 ping 192.168.50.1`（部门C → 信息中心）→ **不通**（被 ACL 100 拦住）
4. `PC0 ping 218.75.230.30`（部门A → 公网 Web）→ 通
5. 各路由器 `show ip route` → 静态默认路由逐级指向下一跳
6. `show ip ospf` 之类不用看（本用例全静态路由）

**注意**：这个 pkt 是**复制设备块**做出来的骨架，第一次在 PT 里打开
可能需要确认一下设备是否都在、接口是否正常。
